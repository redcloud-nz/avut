## v0.9.1 (Philomel)

Patch fixing two production crashes reported after v0.9.

### Highlights

- **Skill package import no longer times out on a shared transaction** — the
  whole import (package, groups, skills) was committed as one batched
  transaction bounded by Prisma's default 5000ms timeout, and unchanged rows
  were rewritten unconditionally. A production import hit `P2028`
  ("transaction expired") outright. Each changed row now commits as its own
  transaction, correlated by a log batch, and unchanged rows are skipped
  entirely. (#165)
- **D4H team sync recovers instead of crashing on a concurrent apply** —
  starting a second sync for the same team while an earlier one was still
  running server-side (e.g. clicking out of the sync dialog and reopening it)
  could make both requests race to create the same `TeamMembership` row,
  crashing the loser with a raw unique-constraint error. The loser now adopts
  the row the other request created instead of failing. (#164)
