## v0.11.1 (Laburnum)

Patch fixing standalone skill checks and tightening session configuration.

### Highlights

- **Checks added on the Checks page count in reports** — `createSkillCheck`
  left standalone checks at the `Draft` default, and nothing ever moves a
  standalone check on, so they never reached the reports. They're now created
  as `Include`. The Add Skill Check dialog no longer suggests it's for
  historical results (back-dating is #386), and the help cards and guides say
  these checks count. Because they now skip review, the server also checks
  each one: the assessor must be the person recording it, the assessee a
  person in the organisation, and the skill one it can assess. Reports refetch
  after a check is added. (#368)
- **Session configuration only accepts the organisation's own personnel and
  skills** — adding assessees or skills to a session now rejects a person from
  another organisation or one that's deleted, and a skill from a package the
  organisation doesn't subscribe to or one that's deleted. All three
  configuration changes (personnel, skills, assessors) also take the session
  lock, so they can't race an approval. (#383)

### After deploying

Checks added on the Checks page before this release stay `Draft`. #368 has the
SQL to find and fix them by hand.
