## Waves

The waves set a rough order, not hard gates.

- **Wave 1** items are independent and can each be done in a sitting.
- **The modules-folder refactor** comes straight after wave 1, while nothing else is in flight.
- **Wave 2** items need a design decision before building (see [Decisions needed](#decisions-needed)).
- **Wave 3** items are long-path work in their own worktrees. They start once the refactor has merged, so they're built on the new layout rather than rebased onto it.
- **Wave 4** items are follow-ups filed during wave 3, added on 2026-10-21.

Path: **quick** means `/avut-develop-feature` implements it in-session. **long** means a reviewed plan in a worktree. Each row is one PR unless it says otherwise.

## Decisions needed

These must be settled before building the item. Ask for each one at pickup rather than guessing.

- **#369, decided 2026-10-16:** unpublishing (and therefore archiving) withdraws the skills from existing subscribers' sessions and reports. They can still open the package in the catalogue and unsubscribe.

- **#144: D4H members with blank or duplicate email.** Exclude and report them, de-duplicate with a collision report, or allow the merge deliberately.
- **#175: whether `integrations.d4h.enabled` is enforced server-side or is presentation-only.** This plan assumes it's enforced.
- **#342 item 4: what subscribers see of a package's history**, if anything.
- **#418, decided 2026-10-21:** deleting a skill group cascades to its active skills, and restoring the group from the Rubbish bin restores them.
- **#402, decided 2026-10-21:** a package in its author's Rubbish bin shows to its subscribers as withdrawn, as unpublished and archived packages do since #369. Subscriptions aren't dropped.
- **#173, decided 2026-10-21:** delete the unmounted import-from-D4H dialog and `createTeamFromD4H`, rather than mount it. Creating a team, then Link to D4H and sync, stays the one path.
