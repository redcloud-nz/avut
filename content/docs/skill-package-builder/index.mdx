# Skill Package Builder

A **skill package** is a set of skill groups and skills that any organisation
can subscribe to from Skill Track's [Packages](/docs/skill-track/packages).
The Skill Package Builder is where your organisation writes and maintains the
packages it publishes. You need the **Skills Author** role, and the module
turned on in **Organisation Settings**.

## Writing a package

**New** starts a package. Open it to add its **skill groups**, and the
**skills** in each group.

<Screenshot

  caption="A package's page: its details, its groups and skills, and the package menu."
/>

A skill's **Revalidation Frequency** is in months. It decides when a pass
expires in [reports](/docs/skill-track/reports): a pass recorded 13 months ago
on a skill with a frequency of 12 shows as Expired. A frequency of 0 means a
pass never expires.

Packages aren't versioned. Once a package is published, every change you make
reaches its subscribers straight away.

## Publishing and archiving

The package's menu (⋮) controls who can see and use it:

- **Publish** offers it to every organisation in Skill Track's **Packages**,
  ready to subscribe to.
- **Unpublish** takes it out, so nobody new can subscribe, and **withdraws** it
  from existing subscribers: its skills leave their sessions and reports until
  you publish it again. The checks they recorded are kept.
- **Archive** marks a package you've finished with. Archiving also unpublishes
  it, so it's withdrawn the same way. **Restore** brings it back, but doesn't
  publish it again: do that yourself when it's ready.
- **Delete** unpublishes the package and moves it to the
  [Rubbish bin](/docs/admin/rubbish-bin). Subscribers lose its skills straight
  away, but still see the package, marked **Withdrawn**, so they can
  unsubscribe. A skill that another organisation has recorded checks against
  can't be purged from the bin.

Subscribers see a withdrawn package as **Subscribed · Withdrawn** — see
[Withdrawn packages](/docs/skill-track/packages#withdrawn-packages).

Deleting a skill group works the same way for its skills: they leave
subscribers' sessions and reports, until you recover the group from the
Rubbish bin.

## History

**History**, in the package's menu, lists every change to the package, who made
it and when, including changes to its groups and skills. Open an entry to see
what changed. Each group and skill also has its own **History**, in its menu.

## Moving a package

**Export .json**, in the package's menu, downloads the whole package as a file,
to copy it to another organisation or another AVUT instance.

**Import**, on the package list, loads that file. A package that's already here
is updated in place, anything the file leaves out is archived, and the result is
always unpublished, so you can check it before publishing.
